# 接入契约（数据端）

> 给**工具方（接入方）**看的：要接入本平台，你得满足什么。
> 字段定义见 [数据契约](../共享层/数据契约.md)；`tool_id` 的来源见 [工具注册表](../共享层/工具注册表.md)。

---

## 一、把责任反转给接入方

平台不去逐个适配工具，而是定一份契约，接入方负责满足。契约要落成三样**具体**的东西，缺一不可：

1. **字段文档**：每个字段的含义、必填/选填、类型、示例。
2. **机器可校验的格式定义**：如 JSON Schema。数据进入接入层时**自动校验**，不合规当场打回——这是契约的「牙齿」。
3. **参考 SDK / 示例代码**：让能配合的工具直接抄，降低接入成本。

契约中必须写明的几条接入方义务：

- **工具自报为主路**：能改代码的工具，在调用或按钮**触发点**把数据报给平台统一上报 API（参考 SDK 是这一步的便捷封装，也可自行实现上报）。改不了代码的黑盒才走转发服务 / 独立 key 兜底，转发不是必经总闸。
- **接住并回传门户注入的身份**：工具从平台入口被打开时，平台会注入 `user_id`，工具上报时原样带回；绕过入口直接使用的，使用者记为匿名。
- **流式调用方必须开启 usage 返回**：流式（SSE）响应默认末尾不带 usage（OpenAI 兼容接口需显式开 `stream_options.include_usage`），不开则 token 全为 NULL。token 在流结束时才齐，须在流结束后再记完整记录。
- **失败 / 超时也必须上报**：这恰是「哪个工具/中转站不稳定」的关键数据，最容易被漏记，契约强制要求。
- **异步任务两段式**：先提交（拿 task id）、后查状态（拿耗时与 `cost`/结果），采集逻辑分两段，token 字段留 NULL、成本走源头返回的 `cost`（`cost_source = source`）。

**兜底通道**：对既给不全数据、又改不了的工具，让其走本地转发服务，由平台「代它」采集到能采集的部分（至少 token + 耗时），按统一格式入库。满足不了完整契约也能进来，只是数据最粗。
契约负责「能配合的自己送上门」，兜底负责「不能配合的平台代采、一个不漏」。

## 二、tool_id 的来源 → 工具注册表

`tool_id` 由平台统一分配，工具接入前先在**工具注册表**登记。该表已升级为**共享层资产**（数据端接入 + 使用端门户展示共用），字段与说明见 [共享层-工具注册表](../共享层/工具注册表.md)。

> 与**用户账号表**（管「人」/`user_id`，见 [架构-入口门户与账号体系](../总则/架构与原则.md)）分工：注册表管「工具」/`tool_id`。

## 三、必须预先处理的边角情况

实现时早晚撞上，脚手架要预留位置：

- **流式输出**：token 数与最终结果在流结束时才齐，采集需在流结束后再记完整记录，不能请求一发就记。
- **失败 / 超时请求**：最容易漏记，但恰是「哪个工具/中转站不稳定」的关键数据。契约必须要求失败也上报。
- **异步任务类工具**（如生成图片/视频：先提交任务、后取结果）：耗时与结果分两次拿，采集逻辑是两段式，SDK 与 schema 要能描述。
- **「一次使用」的界定**：由工具按触发点自定义（如按钮点击即一次），记录是**触发式埋点**而非平台自动观测；一次使用内的多次调用用同一 `conversation_id` 串联。
- **不调大模型的工具**：无 token / 成本，圈二留 NULL，只记圈一（次数 / 耗时 / status）＋（可选）输入输出 / metadata。
- **敏感内容边界**：见 [数据契约](../共享层/数据契约.md) 的「敏感内容策略」一节。
