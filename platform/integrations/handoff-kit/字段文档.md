## 圈一：公共字段（硬性必填，任何工具都得给）

| 字段 | 类型 | 必填 | 说明 |
|---|---|---|---|
| `record_id` | UUID | ✅ | 记录唯一 ID，客户端生成，用于异步上报的幂等去重 |
| `schema_version` | string | ✅ | 本条记录遵循的数据契约版本（如 `v0.2`）；与代码/Git 版本无关，库里混存多版据此解析 |
| `tool_id` | string | ✅ | 哪个工具，由平台统一分配的固定 ID（见 [工具注册表](../shared/registry/)） |
| `conversation_id` | string | ✅ | 会话/任务 ID，把「一次使用」内的多次调用串起来。何为「一次使用」由工具按触发点自定义；最小记录单位是一次 API 调用，分析层按本字段聚合 |
| `start_time` | timestamp | ✅ | 调用开始时间（UTC，ISO 8601） |
| `end_time` | timestamp | ✅ | 调用结束时间（UTC） |
| `duration_ms` | integer | ✅ | 耗时（毫秒），建议采集端测量，避免跨机时钟偏差 |
| `status` | enum | ✅ | `success` / `failed` / `timeout`。失败/超时也必须上报 |
| `ingested_at` | timestamp | 服务端写入 | 入库时间，接入层落库时盖章，区别于事件时间，便于处理晚到/异步数据。**客户端上报可不带** |

## 圈二：LLM 专属字段（调大模型的工具填，普通工具留 NULL）

| 字段 | 类型 | 说明 |
|---|---|---|
| `model` | string | 模型名 |
| `prompt_tokens` | integer | 输入 token（**归一化字段**，见下） |
| `completion_tokens` | integer | 输出 token（归一化字段） |
| `total_tokens` | integer | 总 token（无则采集端 = 输入 + 输出 自补） |
| `cost` | decimal | 本次成本（可空） |
| `cost_source` | enum | `source`（源头直接返回，如异步任务的 cost）/ `computed`（分析层按价表算）。区分「事实」与「算出来的值」 |

> **Token 归一化（必读）**：不同接口/中转站 token 字段名不统一。OpenAI 兼容接口返回 `usage.prompt_tokens / completion_tokens / total_tokens`；Claude Messages 接口只返回 `usage.input_tokens / output_tokens`（无 total）。**采集端负责把各家原始字段映射进上面这套统一字段**（Claude 的 input→prompt、output→completion、total 自补）。平台只定统一目标字段，映射由采集端按契约完成。
>
> **缓存/推理 token**：当前对接的中转站（APIMart）不返回缓存命中、推理 token 拆分，故**不单设列**；将来某供应商返回此类明细，塞进 `metadata` 即可，不动主表。
>
> **价格→金额换算后置**：本阶段以 **token 计数准确** 为主，token→金额换算后置。真正显示成「钱」时需一张**带生效时间的价格表**（每个 model 价格带 `effective_from/effective_to`），否则重算历史成本会用错价。此表结构留待后续阶段，本轮不建（建表 SQL 中仅注释留位）。

## 圈三 + 弹性选填

| 字段 | 类型 | 说明 |
|---|---|---|
| `user_id` | string | 使用者。**门户注入**：从平台入口打开工具时由平台注入真实使用者；无法归属到人时（绕过入口 / 黑盒工具）记为**匿名**（`anonymous`） |
| `team_id` | string | 所属团队（随 `user_id` 解析；无法归属时匿名/空） |
| `result_quality` | float | 结果质量信号（如用户点赞/采纳的归一化分值），ROI 分子占位之一。落库列是 `REAL`，**只有数值会入库**：契约校验虽放行字符串（圈三不拒收），但非数值（如 `good`/`bad` 这类 enum 形态）会在落库时被静默丢成 NULL。**enum 形态的质量请放 `metadata`**，别塞这里 |
| `adopted` | boolean | 结果是否被采纳，ROI 的关键输入 |
| `input_content` | text | 输入原文（**通用选填**：任何工具皆可记，不限大模型；受敏感策略约束，见下） |
| `output_content` | text | 输出原文（通用选填；受敏感策略约束） |
| `metadata` | JSONB | **自由口袋**：工具特异数据任意塞键值对，加字段不改主表 |

> **必填 vs 选填**：圈一是入场券，给不出不许接；质量/采纳/输入输出内容是弹性选填，有就让分析多算几个维度。`user_id` **不做硬必填**——走门户的注入真人、绕过的记匿名，**始终不阻断入库**。绝不能把选填设成会拒收的必填。
>
> **ROI 的「产出/价值」**：分母（cost）已有；分子（产出/价值）工具自身通常产生不了，需另设反馈信号（人工打分 / 采纳率 / 业务回填）。用 `result_quality`、`adopted` 占位，具体用什么信号代表产出**待定，需人工确认**。

## 敏感内容策略（待人工确认）

> ⚠️ **本节为占位，需人工确认。** 一开始不定，后面极难补。

`input_content` / `output_content` 是否存储、存全文还是摘要、**谁能在看板上查看这些原文（读取侧权限控制）**，按工具分级配置。

- 本平台**不做写入侧鉴权**：内部局域网工具发来的是真实使用数据，`tool_id` 由平台统一分配，「这条谁发的」靠固定 ID 解决，恶意伪造不在威胁模型内。真正要管的是**读取侧**——谁能看含提示词/生成结果的原文。读取侧权限按人分级，挂靠在用户账号表角色上，**细则待定**。
