# 钉钉免登打通数据门禁 — 设计文档

- 日期：2026-06-12
- 状态：已与用户确认决策，待写实现计划
- 关联：决策 #38（钉钉组织同步 + 部门治理）、决策 #44（读取侧最小登录门禁）、P2 密码登录退役

## 1. 背景与问题

门户当前从钉钉工作台/快捷指令打开后，进入「数据汇总/明细」页时仍弹出一个独立的用户名/密码登录框（决策 #44 的最小门禁，走 `/auth/login`，与钉钉身份是两套）。用户体验割裂：钉钉已登录，却要再手输一次密码。

根因：前台**未接钉钉免登 JSAPI**，后端拿不到钉钉身份，只能用平台账号二次认证。钉钉组织同步只做到 Phase A（人员/部门入库），「免登拿身份 → 据身份鉴权」这条链路没打通。

## 2. 目标与非目标

**目标**
- 钉钉客户端内打开门户即免登，自动拿到钉钉身份，无需任何手动登录。
- 敏感数据（统计汇总 + 调用明细）仅 admin/超管可见。
- 提供「成员权限管理」面板，超管可增减 admin。
- 彻底移除密码登录（`/auth/login`、`authenticate`、前台密码框），完成 P2 密码退役。

**非目标（本轮不做，留后续）**
- 部门/角色细粒度分级（如「只看本部门数据」）—— 仍待定。
- 调用明细的字段级脱敏预览。
- 非钉钉环境的访问入口（本轮明确：非钉钉环境直接挡住）。

## 3. 角色模型

| 身份 | 认定方式 | 工具门户/历史生成 | 统计+明细 | 增减 admin |
|---|---|---|---|---|
| 超管 | 钉钉 userid ∈ 配置 `BOOTSTRAP_ADMIN_DINGTALK_USERID` | ✅ | ✅ | ✅ |
| admin | 超管在面板里设的（DB `user_account.role='admin'`） | ✅ | ✅ | ❌ |
| 普通员工 | 组织同步进来的其他账号（`role='user'`） | ✅ | ❌ | ❌ |

判定规则：
- `can_view_data`（看统计+明细）= `role == 'admin'` 或 `userid ∈ 超管配置`
- `can_manage_admins`（增减 admin）= `userid ∈ 超管配置`，**只认配置，UI 永不可改**——天然只有超管能管。
- 超管配置里的 userid 隐含拥有 admin 的一切能力（即使 DB role 仍是 user 也按 admin 处理）。

## 4. 整体链路

```
钉钉客户端打开门户
  → 前台检测 dd 对象 → dd 免登拿 code（dd.runtime.permission.requestAuthCode）
  → POST /auth/dingtalk { code }
  → 后端用 appKey/appSecret 调钉钉 user/getuserinfo 换 dingtalk_userid
  → 按 dingtalk_userid 查 user_account（组织同步已建好）
  → 判定身份（超管/admin/普通）→ 签发 token（claims 带 role + is_superadmin）
  → 前台用 token 取数；非 admin 看统计/明细时前后端均拒绝
普通浏览器打开（无 dd）→ 不显示密码框，提示「请在钉钉客户端内打开」
```

## 5. 后端改动

### 5.1 新增免登换身份能力（复用现有钉钉客户端）
- 在 `backend/org_sync/client.py`（或同模块新增）加 `get_userinfo_by_code(code) -> dingtalk_userid`，走经典接口 `POST /topapi/v2/user/getuserinfo`（oapi，与现有 `gettoken` 同一 appKey/appSecret、同一缓存 token 机制）。
- 不新增密钥：复用组织同步已在用的 appKey/appSecret（决策 #34 密钥纪律）。

### 5.2 新增接口
- `POST /auth/dingtalk { code }` → `TokenResponse`：免登 code → dingtalk_userid → 查账号 → 判定身份 → 签发 token。账号不存在（未同步）时返回明确错误「账号未同步，请联系超管」。
- `GET /auth/admins`（超管专属）：列出员工（`display_name` + `dingtalk_userid` + 当前 role + 是否超管），供管理面板渲染。
- `POST /auth/admins/{user_id} { role: 'admin' | 'user' }`（超管专属）：设/撤某员工 admin。禁止修改超管自身（超管由配置定，不在此接口范围）。

### 5.3 token claims 扩展
- `issue_token` 的 claims 增加 `is_superadmin: bool`（由「userid 是否在配置」算出）。`role` 已有。
- 统计/明细相关读接口（`/analytics/*`）的依赖项从「有 token」收紧为「`can_view_data`」。

### 5.4 删除
- `POST /auth/login`、`authenticate()`、`LoginRequest`、密码校验路径。
- `passwords.py` 若仅被密码登录使用则一并清理（删不注释，§代码规范）。
- 注：`user_account.password_hash` 列暂保留（可空，无人写入），避免一次性改表；后续可在数据契约层评估是否删列。

## 6. 配置

- 新增环境变量 `BOOTSTRAP_ADMIN_DINGTALK_USERID`：逗号分隔的钉钉 userid 列表（默认仅超管本人一个，留多人余地）。写入 `platform/.env`。
- 新增 `DINGTALK_CORP_ID`：前台 `requestAuthCode` 需要的企业 corpId。前台静态页不直接读 `.env`，故新增一个轻量只读接口 `GET /auth/config`（无需鉴权，仅暴露 corpId + appKey 这类前台必需的公开标识，不含 secret），前台启动时拉取。
- 复用现有 `DINGTALK_APP_KEY` / `DINGTALK_APP_SECRET`（组织同步已配）。

## 7. 前台改动（`platform/apps/web/index.html`）

- 启动时拉 `GET /auth/config` 拿 corpId。进入需要身份的页面时：检测 `dd` 对象 → 调 `dd.runtime.permission.requestAuthCode`（corpId 来自上一步）拿 code → `POST /auth/dingtalk` 换 token，存内存/会话。全程无手动登录。
- 无 `dd` 对象（普通浏览器）→ 不渲染密码框，渲染「请在钉钉客户端内打开」提示。
- 删除现有密码登录面板（`ensureLoginPanel` / `bindLoginPanel` / `data-login-panel` 相关）。
- 统计页 + 明细页：仅 `can_view_data` 渲染；非 admin 显示「你不是管理员，无权查看，请联系超管开通」。
- 工具门户首页 + 自己的历史生成：所有免登成功的员工可见。
- 新增「成员权限管理」面板：仅超管可见，列员工、一键设/撤 admin，调 `GET/POST /auth/admins`。

## 8. 错误处理

- 免登失败（code 无效/过期）：提示「钉钉登录失败，请重试或重开页面」。
- 账号未同步：提示「账号未同步，请联系超管在后台同步组织」。
- 非 admin 访问数据端接口：后端返回 403，前台显示无权限提示（不暴露数据）。
- 钉钉云接口不可达：超管/admin 仍可见提示，记录服务端日志。

## 9. 测试

- 单测（沿用 ASGITransport，无需 uvicorn）：
  - `/auth/dingtalk`：mock 钉钉客户端返回 userid → 命中已同步账号 → 签发 token；userid 未同步 → 报错。
  - 身份判定：超管配置命中 → is_superadmin/can_view_data 为真；DB admin → can_view_data 真、can_manage 假；普通 → 皆假。
  - `/auth/admins` 系列：超管可列/可改；非超管 403。
  - 数据端读接口：非 admin 403，admin/超管 200。
- mock 钉钉 `user/getuserinfo`，不打真实钉钉云。
