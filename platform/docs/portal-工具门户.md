# 工具门户（使用端）

> 面向普通使用者的入口前端。架构定位见 [架构与原则](architecture-架构与原则.md)。
> 工具目录数据来自 [共享层-工具注册表](registry-工具注册表.md)；使用情况来自共享层事件表（跨端只读）。

---

## 一、定位

使用者登录后的统一入口：分类列出可用工具、按偏好/使用情况排序、AI 按需求推荐，点卡片经局域网链接打开工具。打开时平台注入 `user_id`，工具上报时带回（机制见 [架构-入口门户与账号体系](architecture-架构与原则.md)）。

实现上是「卡片 + 局域网链接」的**轻前端**：数据全部来自共享后端，门户本身不存业务数据，也不写分析结论。

---

## 二、核心功能

### 1. 分类工具列表

读 [工具注册表](registry-工具注册表.md) 的 `category` 字段分组，**卡片式**展示。每张卡片以**功能缩略图**（`thumbnail`）为主体，配 `icon` + `display_name` + 一句 `description`，点击跳 `launch_url`（卡片视觉与交互详见 §三 界面设计）。仅展示 `enabled = true` 的工具。

### 2. 排序逻辑

三级，优先级自上而下：

- **用户自定义偏好**：使用者可手动置顶 / 排序，偏好**按人保存**。
- **自动排序**（无自定义时）：按**使用频次 / 最近使用时间**自动靠前。数据来自共享层事件表按 `user_id` + `tool_id` 的聚合（跨端只读，不在门户侧重复存）。
- **兜底**：无任何使用信号时，用注册表 `sort_weight`。

### 3. AI 工具推荐

使用者输入「想实现什么功能」，AI 基于注册表里各工具的 `description` 做**语义匹配**，推荐合适工具。实现上接一个 LLM API 即可（地址 / Key 走配置、零硬编码，呼应 [代码规范](code-standards-代码规范.md) §七）。

## 三、界面设计（UI）

> **本节为门户 UI 定稿。** 配套**已确认的视觉参考稿**（可点、浅/深可切、数据为占位）：[mockups/stitch_smart_tool_hub/code.html](mockups/stitch_smart_tool_hub/code.html)（设计系统说明见同目录 [DESIGN.md](mockups/stitch_smart_tool_hub/DESIGN.md)）。前端按本节 + 该参考实现；该文件以本节为准，不是另一份 SSOT。

**布局范式：居中搜索框 + 视图 chips + 单一网格**（启动器风，决策 #42）。桌面优先（局域网内网页）、卡片圆角，网格列数随窗口自适应。**支持浅色 / 深色双主题**——同一套布局只换配色，顶栏（吸顶）放一个**日 / 夜切换**按钮，默认浅色。门户要注入 `user_id`，故**必须登录才进**。

### 首页结构（自上而下）

```
┌──────────────────────────────────────────────────────────┐
│ [⬢ 内部工具门户]              [☀/🌙 日夜] [👤 当前用户]    │  吸顶栏（含日/夜切换）
├──────────────────────────────────────────────────────────┤
│        ┌──────────────────────────────┐                   │  居中大搜索框
│        │ 🔍 搜工具，或描述你想做什么… [✨AI推荐] [搜索] │     │
│        └──────────────────────────────┘                   │
│              〔全部〕                                      │  视图 chips（首版仅「全部」）
│  ┌────┐ ┌────┐ ┌────┐                                    │  单一网格（按排序逻辑排列）
│  ┌────┐ ┌────┐ ┌────┐ …                                  │
└──────────────────────────────────────────────────────────┘
```

- **首版只有「全部」一个视图**：单网格按 §二 排序逻辑排列全部上架工具。chips 行结构保留，**后续视图**（「最近使用」「按分类」「按部门」——部门数据已由钉钉同步落库，可见性治理见 [钉钉设计稿](dingtalk-钉钉组织与部门治理/README-总览与索引.md)）按需追加，不另改布局。
- **收藏 / 拖拽排序**同样后置：等收藏功能实现时以「我的收藏」视图或置顶形式并入，不再单设分区。

### 卡片（图片式「媒体卡」）

```
┌────────────────────────┐
│      功能缩略图 thumbnail │  ← 占卡片主体；无图时用「icon+名称+色块」占位图
│              〔分类标签〕 │  ← category 小标签叠右上角
├────────────────────────┤
│ [icon] 工具展示名         │  ← icon + display_name
│ 一句话功能介绍…            │  ← description（超出省略）
│                 打开 ↗   │  ← 跳 launch_url（新标签页）
└────────────────────────┘
```

- 缩略图取注册表 `thumbnail`；**缺图自动生成**「`icon` + `display_name` + 色块」占位图（不留空、不强制工具方必传）。
- 点卡片主体 → 新标签页打开 `launch_url`（打开瞬间注入 `user_id`）；hover 缩略图轻微放大/亮起。仅展示 `enabled = true`。

### 三块交互行为

| 区域 | 数据来源 | 行为 |
|---|---|---|
| **搜索框打字** | 本地已加载工具列表 | 即时按 名称 / 简介 过滤，**零后端、零 token**；无结果提示「试试 ✨ 让 AI 推荐」 |
| **✨ AI 推荐** | 把输入当需求发 LLM，匹配各工具 `description` | 框下展开「AI 推荐结果」面板：几张紧凑卡片 + 一句推荐理由，可直接打开；点空白收起；调用失败提示重试、不影响其余浏览。**后端推荐能力未实现前，前端先占位**（参考稿即此形态） |
| **★ 收藏（后置）** | 偏好按人存（共享后端） | 实现时以「我的收藏」视图或置顶并入单网格；未收藏的按频次/时间自动排，无信号用 `sort_weight` 兜底 |

### 状态与边角

- **登录页**：账号 + 密码（管理员发初始密码、用户自改，见 [账号体系](architecture-架构与原则.md)）。
- 搜索无结果 → 「没找到，试试 ✨ 让 AI 推荐」。

---

## 四、与数据端共享的边界

- **只读共享数据**：门户读注册表（展示信息）+ 事件表聚合（排序），**不写**分析结论。
- **写入侧走统一契约**：门户产生的「打开工具」动作，经采集层按统一 [数据契约](schema-数据契约.md) 入库（与其他工具上报一视同仁），不另开数据通道。

## 五、待定（需人工确认）

- 排序「使用频次 / 时间」的具体取数窗口（近 7 天？全期？加权？）。
- 用户自定义偏好的存储位置（扩展用户账号表，还是单建偏好表）。
- AI 工具推荐这次 LLM 调用，是否也作为「一次使用」纳入统计。
- AI 推荐用哪家模型 / 部署在哪，与中转站地址同走配置，**待定**。
