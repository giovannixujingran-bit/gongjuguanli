# 部门化可见性治理（Phase B · 设计稿 · 待实现）

> 本分册定义在 [Phase A 钉钉打通](dingtalk-integration-钉钉集成.md) 的组织数据之上，门户如何**按部门控制工具可见性**。
> 总览见 [README](README-总览与索引.md)；数据结构与判定算法见 [数据模型](data-model-数据模型.md)；关联决策 **#38**。
> **软治理**：只控门户「可见 / 上架」，不碰工具本身（不破坏「不做写入侧鉴权」原则，决策 #7）。

---

## 一、治理模型

一句话：**工具默认是部门私有的，想跨部门共用就把对方部门加白名单，公司通用的一键全开。** 三种情况：

| 情况 | 谁能看到 | 怎么设 |
|---|---|---|
| **默认（不特别设置）** | 只有**归属部门及其子部门** | 工具登记时挂一个 `owner_dept_id`（归属部门） |
| **跨部门共用** | 归属部门 + **被显式授权的部门**（含其子部门） | 把对方部门加进 `tool_visible_department` 白名单 |
| **公司级通用** | 所有登录用户 | 勾上 `visible_to_all` |

子部门自动跟随：开给「研发中心」，其下前端组 / 后端组等自动可见，不用逐个加（即「向下级联」，见 §二）。

---

## 二、可见性规则

依据 [数据模型 §五](data-model-数据模型.md) 的判定算法。工具 `T` 对登录用户可见，当且仅当满足任一：

| # | 条件 | 含义 |
|---|---|---|
| 1 | `T.visible_to_all = true` | 公司级公共工具，所有人可见 |
| 2 | 用户某部门落在 `T.owner_dept_id` **或其子部门** | 默认：本部门（含下属子部门）可见 |
| 3 | 用户某部门落在 `T` 的 `tool_visible_department` 白名单**或其子部门** | 跨部门显式授权 |
| — | 用户是 **admin** | 看全部（管理需要，不走过滤） |

**向下级联**：把工具开给「研发中心」，其下所有子部门自动可见，维护白名单时不必逐个子部门点。算法上用「用户部门取祖先链闭包」高效实现（见 [数据模型 §五](data-model-数据模型.md)）。

叠加现有门户规则：仍只展示 `enabled = true` 的工具（[门户 §二](../portal-工具门户.md)）。

## 三、门户侧改动

[门户](../portal-工具门户.md) 在加载工具目录时，从「对所有登录用户一视同仁」改为**按当前用户部门过滤**：

1. 免登拿到 `user_id` → 查 `user_department` 得部门集合。
2. 递归取部门祖先链闭包（PG `WITH RECURSIVE` 走 `department.parent_id`）。
3. `SELECT` 注册表，过滤 `enabled = true AND (visible_to_all OR owner_dept_id IN 闭包 OR EXISTS 白名单命中闭包)`。
4. 其余门户行为（分类卡片、排序三级、收藏、AI 推荐）**不变**，只是候选工具集先被部门过滤了一道。

> 门户仍是「读取侧」：只决定**看不看得到**，不阻止知道 `launch_url` 的人直接访问（软治理边界，决策 #7 内网威胁模型）。真要硬锁少数敏感工具，属硬治理，本设计未采纳（见 [README](README-总览与索引.md) §二）。

## 四、admin 维护白名单

| 项 | 设计 |
|---|---|
| 在哪维护 | **数据端后台**（[架构 §一](../architecture-架构与原则.md) 的「接入与账号管理」一并扩展），走 admin 门禁（决策 #31/#32） |
| 维护什么 | 设工具的 `owner_dept_id`、勾 `visible_to_all`、增删 `tool_visible_department` 白名单 |
| 端点 | 扩展注册表更新接口（在 `POST /registry/tools` 之外加治理字段的更新端点，沿用同一 admin 门禁） |
| 部门选择 | 从已同步的 `department` 树里选，不手填——保证引用真实部门 |

> 与决策 #32 的衔接：`POST /registry/tools` 发放通道 MVP「只发接入字段」，展示字段与**治理字段**都属「后续由后台 / 更新接口设置」，本设计正是补上治理字段那部分。

## 五、与读取侧权限的关系（边界澄清）

本设计治理的是**「门户里看得到哪些工具卡片」**，不是**「上看板能看哪些数据 / 原文」**：

| 治理对象 | 归属 | 状态 |
|---|---|---|
| 门户工具可见性（本设计） | 使用端 · 软治理 | 本设计落地 |
| 看板读取侧权限（谁能看明细 / 原文） | 数据端 · 读取侧分级 | 仍**待定**（决策 #17/#34），不在本设计范围 |

两者都可能挂在「用户 + 角色 / 部门」上，将来读取侧权限做时，**可复用本设计的部门维度**（user_department）作为分级依据之一——但那是独立的后续工作，本设计只把组织数据备好。
