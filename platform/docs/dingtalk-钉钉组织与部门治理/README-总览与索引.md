## 一、一句话目标

**员工在钉钉里点开门户 → 平台秒认出「张三·财务部」→ 只给他看财务部能看的工具。** 全程零密码、零额外配置。

---

## 二、确定的设计取舍（详见各分册 + 决策 #38）

| 维度 | 选定 | 否决的替代 |
|---|---|---|
| 核心痛点 | **权限治理**（谁能用什么） | 发现/组织、接入生命周期（后续可叠加） |
| 治理强度 | **软治理**：只控门户「可见 / 上架」，不碰工具本身 | 硬治理（launch_token 卡权限）——会破坏「不做写入侧鉴权」原则（决策 #7） |
| 组织数据来源 | **钉钉为唯一源**，同步部门树 + 人员 | 平台自管 / 一次性导入（会漂移） |
| 登录认人 | **钉钉免登**（H5 微应用）为唯一登录；密码体系退役 | 仍用密码（脱节、体验差） |
| 可见性模型 | **工具默认只归本部门看；要给别的部门用，就把那个部门加进白名单；公司通用的一键全开** | 默认全开、标签订阅 |
| 部署可达性 | 本轮定**只在公司网络内用 PC 钉钉**（内网地址即可达） | 手机/外网（需穿透/反代，后续再评估） |

## 五、已定关键参数（决策 #38）

| # | 参数 | 决定 | 落点分册 |
|---|---|---|---|
| P1 | 组织同步频率 | **每小时一次定时 + 管理员手动触发端点** | 钉钉集成 §3.2 |
| P2 | 密码体系 | **完全退役**，钉钉免登为唯一登录；首个 admin 由 seed 脚本绑定钉钉 `userid` 引导 | 钉钉集成 §五/§六 |
| P3 | 同步未覆盖的新员工 | **即时拉一次**该员工详情，建账号后登入 | 钉钉集成 §四 |
| P4 | 白名单存法 | **单独关联表** `tool_visible_department`（不用 JSONB 数组，利于 join） | 数据模型 §4 |
| P5 | 门户可达性 | **只在公司网络内用 PC 钉钉**（手机 / 外网后续再评估穿透/反代） | 钉钉集成 §二 |
| P6 | 删除部门 / 离职人员 | **软删保留**（`active = false`），不硬删，避免引用悬空 | 数据模型 §二 |
